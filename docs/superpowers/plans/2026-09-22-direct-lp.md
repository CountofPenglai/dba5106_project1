# Direct Asset Linear Programming Implementation Plan

> **For agentic workers:** Use test-driven development for implementation and independent subagents for bounded implementation/review. Track evidence in `.lp-work/progress.md`.

**Goal:** Replace learned three-way decision mixtures with daily LP solutions for all 98 asset weights, compare both existing LASSO forecast windows, and retain every older experiment.

**Architecture:** Existing causal forecasters supply daily expected returns. A separate LP module builds historical MAD and uncompounded absolute-drawdown constraints. A chronological runner solves asset weights directly, records actual compounded performance, and exports a frozen configuration for the reserved final test.

**Tech Stack:** Existing Python, NumPy, pandas, sklearn; SciPy HiGHS linear programming (already installed, add explicit dependency); unittest.

**Spec:** The design below records the user's approved direct-asset LP request and explicit mathematical definitions needed for a pure LP.

## Global Constraints / Design

- User explicitly authorized implementation. Do not add another approval loop. Preserve all prior changes and 126/252/3-year/two-stage entry points; no remote push.
- Source history begins 2021-08-01, alpha calibration ends 2024-07-31, optional chronological development backtest 2024-08-01..2025-12-31, default evaluation only on validation 2026-01-02..2026-06-30. Reserved August 2026 final test remains untouched in development.
- Forecasts: unchanged 252 complete samples and up to three calendar years; six causal features, equal observations, alpha chosen once with late 3x21 CV then frozen. No theta/model fitting at decision stage.
- Every prediction day's optimization uses only prior returns and forecast mu. Risk history is up to three calendar years, minimum 252 observations.
- Pure LP: maximize mu @ w; sum(w)=1; gross <=1.5; each abs(w_i)<=.05; all historical 1+R_s @ w>=1e-6.
- Let A=R-column_means(R), C=cumsum(R,axis=0). MAD=mean(abs(A@w)). Uncompounded absolute drawdown=max_t(max(0,C_1@w,...,C_t@w)-C_t@w). Both default caps equal the same measure of EW in the identical history. These are proxies, not standard deviation, Sharpe, or compounded relative drawdown.
- Auxiliary variables linearize absolute values and running peaks. Use scipy.optimize.linprog(method='highs'), require success/optimal and independently recompute feasibility. Normalize constraints for numerical conditioning. No hidden EW fallback or acceptance of inaccurate/nonoptimal outcomes.
- Secondary LP minimizes L1 distance to EW subject to the primary predicted-return optimum within a documented absolute 1e-10 daily-return tolerance. This is deterministic solver tie handling, not a learned EW mixture.
- Main model labels LP_LASSO_252d/LP_LASSO_3y; historical-mean controls LP_Mean_252d/LP_Mean_3y share the LP constraints/history. Include EW and the prior direct-U, mixture, and legacy baselines on matching validation dates when a verified reference result is supplied.
- All default LP parameters are fixed before results; no post-hoc risk-parameter search. Synthetic tests may use larger position limits for small asset universes. Impossible user limits fail explicitly.
- Evaluate realized compounded return, daily Sharpe (rf=0, ddof=1), realized std, max relative drawdown, gross, max position and drifted turnover. Report development/validation separately; no claim all metrics or future risk limits are guaranteed.
- Frozen final-test path must check history fingerprint, assets, parameter schema, and all 20 August 3..28 dates; no alpha/decision parameter reselection.

## Review Focus

1. Drawdown starts from zero cumulative P&L; an initial loss and all-negative history must be counted.
2. LP variable default nonnegativity must not accidentally prohibit permitted short positions; validate actual weights after both solves.
3. Tiny/zero EW MAD or drawdown must not permit material relative risk violations or divide by zero.
4. Current/future returns cannot affect current forecasts or optimization; prediction dates and column labels must align.
5. Reference results and reserved-test frozen inputs must be rejected if dates, data, assets, configuration or relevant code provenance differ.

## Interfaces

`portfolio/linear_decision.py`:

```python
@dataclass(frozen=True)
class LPConstraints:
    leverage_limit: float = 1.5
    position_limit: float = .05
    mad_ratio: float = 1.
    drawdown_ratio: float = 1.
    wealth_floor: float = 1e-6

build_lp_context(history, constraints=LPConstraints()) -> LPContext
check_lp_weights(context, weights) -> dict  # actual budget/gross/position/MAD/DD/wealth
solve_linear_portfolio(context, expected_returns) -> tuple[np.ndarray, dict]
```

Context must expose `history`, `equal_weights`, `constraints`, `mad_limit`, `drawdown_limit`; other matrices are internal. Diagnostics are finite JSON/CSV-compatible scalar/string values and include solver status, primary return, final predicted return, secondary gap and actual feasibility values. Accept DataFrame with unique assets or finite ndarray, >=2 dates/assets.

`portfolio/direct_lp.py`: `run_direct_lp(returns, *, config=DirectLPConfig(), constraints=LPConstraints(), forecast_configs=None, risk_window=None, progress=None)` and `run_frozen_lp(returns, frozen, *, progress=None)` return existing `ExperimentResult`. DirectLPConfig contains dates, alpha grid and CV sizes only (no unused gamma settings). Shared IO exporter gets explicit new entry-point code paths. portfolio/lp_reference.py owns verified reference comparison. CLI `run_direct_lp.py` handles fresh output, source loading, optional reference comparison, and explicit frozen August mode.
